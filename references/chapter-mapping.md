# 章节编号识别规则

## 问题位置格式规范

### 正确格式（必须使用）
- ✅ `"第3章第2.1节"`
- ✅ `"第4章表4-1"`
- ✅ `"第6.3节图6-2"`
- ✅ `"第2章第2.5.1条"`

### 错误格式（reviewer需要修正）
- ❌ `"第3035行"` → 转换为章节编号
- ❌ `"第6407行"` → 转换为章节编号
- ❌ `"第1行"` → 转换为章节编号

---

## Reviewer 转换方法

当 reviewer 发现问题位置使用行号格式时：

### 步骤1：读取文档
```python
# 读取文档内容
content = Read(document_path)
```

### 步骤2：定位章节
找到行号所在的章节：
1. 解析文档，识别所有章节标题（如 `# 第1章`、`## 1.1 概述`）
2. 建立章节与行号的映射
3. 找到目标行号所在的最近章节

### 步骤3：修改问题清单
直接修改问题清单中的 location 字段：

```json
// 修正前
{
  "id": "SE-001",
  "location": "第3035行",
  ...
}

// 修正后
{
  "id": "SE-001",
  "location": "第2章第2.5节",
  "original_location": "第3035行",
  "location_corrected": true
}
```

### 步骤4：返回修正结果
无需反馈给其他角色，直接返回修正后的问题清单。

## 章节编号与Markdown标题对应关系

| Markdown格式 | 对应章节编号 | 示例 |
|--------------|--------------|------|
| `# 一级标题` | 第X章 | `# 设计总说明` → 第1章 |
| `## 二级标题` | 第X.Y节 | `## 1.1 概述` → 第1章第1.1节 |
| `### 三级标题` | 第X.Y.Z条 | `### 1.1.1 设计依据` → 第1章第1.1.1条 |

## 问题记录检查清单

在记录问题位置时，请确认：

- [ ] 未使用行号（如"第6407行"）
- [ ] 使用了章节编号（如"第3章第2.1节"）
- [ ] 表格问题标注为"第X章表X-X"
- [ ] 图表问题标注为"第X.X节图X-X"
- [ ] 位置描述清晰可追溯

---

## Reviewer 检查清单

审查问题清单时：

- [ ] 所有 location 字段都不是行号格式
- [ ] 所有 location 字段都使用章节编号格式
- [ ] 已将所有行号格式转换为章节编号
- [ ] 修正后的问题清单已返回给 coordinator
